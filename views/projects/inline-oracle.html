Oracle

Envisioning Oracle Cloud Prototypes

As Principal UX Designer, I rethought Oracle's Accounts search and refinement experience, known internally as "Killer Bee." Sales teams were working with dense account data and needed to look at it from several angles without rebuilding the query each time. I designed the search, faceting, and disclosure patterns, then carried the model from desktop to tablet and phone so the interaction stayed familiar as the available space changed.

Use Case

Desktop: Search and Refinement

Problem Definition

The Accounts workspace carried many filter facets (Killer Rank, Backbone, Focus, Target, Classification, Ownership), and sales teams needed to re-run full queries every time they wanted to look at the data from a different angle.

Hypothesis

A clean search layout that keeps the query, results, and facets in view, combined with faceting that lets users pivot on terms without re-querying, would keep teams in their information-seeking flow.

Method

Wireframes tested a refinement panel where saved search configurations could be shared across a sales team, with the current query always reflected back in the facets so users could see exactly what they were looking at.

Result and next steps

The desktop pattern combined real-time results, contextual disclosure panels on each result row, and saveable refinement sets that could drive recurring content rollups and email digests for the team.

Tablet: Adapting to Limited Horizontal Space

Portrait Mode Results

Portrait mode on the tablet compressed the same rich account data into a much narrower horizontal view, so the desktop table pattern needed to be rethought rather than simply resized.

Hypothesis

Rearranging result items to match the user's flow and available screen real estate, and moving secondary actions into a tap-to-open contextual menu, would preserve rapid seeking, sorting, and filtering in portrait mode.

Method

Tablet prototypes tested tapping a result to reveal a contextual menu, and a single-finger swipe gesture to save or share an entry, extending the same account record with in-situ social and workflow actions.

Result and next steps

The tablet pattern kept the desktop's information density readable in portrait orientation while adding touch-first gestures that had no desktop equivalent.

Responsive UI Studies

Phone: Refinement, Search, and Results

A Single Model, Retained Across Devices

On phone, the same refinement facets, real-time search, and result set had to work with one thumb and a fraction of the screen, while still feeling like the same product as the desktop.

Hypothesis

Retaining device-specific expectations (swipe left from refinement into results, real-time search on every keystroke, a consistent result pattern for quick scanning) would let users move fluidly between devices without relearning the flow.

Method

Phone flows walked through refinement options, real-time search results, swipe-based pagination through results, and a tap-activated "Product Gap Panel" surfacing saved searches, bookmarks, facets, settings, and profile from the bottom navigation.

Result and next steps

The phone experience delivered the full Accounts search and refinement model in a compact, gesture-driven interface, completing a single interaction pattern that scaled from desktop down to phone.
